# Project audit — September 13, 2026

Scope: runtime source, public catalogue ingestion and presentation, private workspace/session flows, CSV import, case selection, monitoring-event processing, rate limits, exports, deployment configuration, dependency advisories, demo instructions and submission documentation. Controlled tests use isolated databases; the real inventory remains untouched. An audit can find and prevent specific failures; passing tests do not prove the absence of every bug or general recall accuracy.

## Fixed findings

| Finding | Result |
| --- | --- |
| CPSC API returned Grizzly planer repair instructions in INIU power-bank recall 26135 | Removed API remedy text from the public dataset and refresh pipeline. The catalogue links to the original CPSC notice for current remedy instructions. No brand-specific replacement logic or invented remedy was added. |

| Rejected CSV file could leave an old reviewed import available | Invalid uploads clear the prior preview; asynchronous file reads cannot overwrite newer input. |

| Concurrent rate-limit requests could all observe a later count | Each request receives its own count from one atomic database statement. |
| Interrupted monitor events could remain stuck in processing | Expired processing claims become retryable; active claims are preserved, exhausted events do not block later events, and old claims cannot overwrite the replacement event status. |

## Hardcoded content retained intentionally

The five official recall records are a dated, selected CPSC snapshot, not generated examples or a comprehensive live feed. Original notice IDs, source URLs and retrieval dates remain factual data. Physical inventory must come from its owner. Controlled inputs remain confined to automated tests and explicitly enabled isolated local fixture mode; hosted fixture mode stays disabled.

Approved domains, request/time limits, fixed safety status names and the documented linked-notice reconciliation are deliberate policy. They are shared configuration or evidence rules, not fabricated business outcomes. No owner/provider credential is embedded in the frontend or source archive.

## Remaining limits

No new paid Anakin investigation was performed during this audit. Historical live calls remain documented separately. The public-data discrepancy demonstrates why original source review still matters. The catalogue does not feed eligibility decisions automatically; investigations retrieve their own approved evidence.

Monitoring retries are operator-initiated recovery, not a durable job scheduler. End-to-end external signed webhook delivery and scheduled monitor activation remain unverified. The app still supports one owner, without tenant isolation, account roles or MFA. Schema changes require reviewed migrations; deployment does not seed or automatically migrate production data.
